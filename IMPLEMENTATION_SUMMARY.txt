IMPLEMENTATION DETAILS
================================================================================

PATTERN USED:
Each async function follows this flow:
  1. Validate input (no loading state for client-side validation)
  2. Get button reference
  3. Show button loading state + overlay with message
  4. Perform async operation
  5. On error: Hide overlay, restore button, show error
  6. On success: Hide overlay, show success, optional delayed action

LOADING STATES TYPES:
  • Full-screen overlay with centered spinner
  • Button-level spinner with disabled state
  • Context-specific loading messages
  • Multi-step feedback (progress → verify → redirect)

ERROR HANDLING:
  • All async operations wrapped in try-catch-finally
  • Proper cleanup in all error paths
  • Button state restored on failure
  • Overlay hidden on error
  • Existing error messages preserved

EDGE CASES HANDLED:
  • Network timeouts (session verification retries 3 times)
  • Duplicate emails (shows error without loading state)
  • Missing DOM elements (safe navigation with ?.)
  • Form field clearing on success (security)
  • Button text restoration from dataset

ISSUES ENCOUNTERED & SOLUTIONS
================================================================================

Issue 1: Button Text Restoration
Problem: When showing spinner, original text was lost
Solution: Store text in button.dataset.originalText before showing spinner

Issue 2: Multiple Button References
Problem: Async operations could create stale button references
Solution: Always query button fresh in error blocks

Issue 3: Static logout() Method
Problem: Static method can't use instance this
Solution: Direct DOM manipulation in logout function

Issue 4: Page Load Overlay
Problem: Overlay on load could conflict with forms
Solution: Hide overlay immediately after session check

Issue 5: Form Listener Duplication
Problem: Complex error handling duplicated in listeners
Solution: Move all logic to handlers, simplify listeners
